데이터베이스의 기본 개념

SQL을 쓰기 전에, SQL이 말을 거는 상대가 무엇인지부터 정리합니다.

1.1데이터베이스와 DBMS

데이터베이스는 정리된 데이터 묶음, DBMS는 그것을 관리하는 프로그램, SQL은 DBMS에게 일을 시키는 언어입니다.

엑셀 파일에 학생 명단을 적어 두는 것도 넓게 보면 데이터 저장입니다. 그런데 학생이 수만 명이고, 상담사 10명이 동시에 고치고, 실수로 지운 내용을 되돌려야 하고, 권한이 없는 사람은 연락처를 보면 안 된다면 엑셀로는 버팁니다. 이런 일을 대신 해주는 프로그램이 DBMS(Database Management System)입니다.

용어뜻비유
데이터베이스 (DB)여러 사람이 함께 쓰려고 체계적으로 모아 둔 데이터의 집합도서관에 꽂힌 책 전체
DBMSDB를 만들고, 저장하고, 찾고, 지키는 소프트웨어 (MySQL, Oracle 등)사서와 도서관 운영 시스템
SQLDBMS에 명령하는 표준 언어 (Structured Query Language)사서에게 쓰는 대출 신청서 양식
스키마DB의 구조 설계도 (어떤 테이블에 어떤 열이 있는지)도서관 층별 배치도
인스턴스특정 시점에 DB에 실제로 들어 있는 데이터오늘 서가에 꽂힌 책들

파일로 관리할 때 생기는 문제를 DBMS가 해결하는 방식

파일 관리의 문제DBMS의 해결
같은 데이터가 여러 파일에 중복 (명단 엑셀, 출석 엑셀에 같은 연락처)한 곳에 저장하고 키로 연결 (정규화)
한쪽만 고치면 값이 서로 달라짐 (불일치)제약조건과 외래키로 무결성 유지
두 사람이 동시에 저장하면 한쪽 내용이 사라짐잠금(lock)과 트랜잭션으로 동시성 제어
컴퓨터가 꺼지면 작업 중 내용 손실로그 기반 회복(복구)
파일 접근 권한이 통째로 열리거나 닫힘사용자·테이블·열 단위 권한(GRANT)

데이터 독립성과 3단계 스키마

DBMS는 데이터를 세 겹으로 바라봅니다. 덕분에 저장 방식(디스크 배치)을 바꿔도 프로그램을 고칠 필요가 없고, 테이블 구조를 바꿔도 사용자 화면은 그대로 둘 수 있습니다.

단계누구의 관점내용
외부 스키마사용자, 응용 프로그램각자 필요한 부분만 본 모습 (뷰). 상담사는 연락처, 강사는 점수만
개념 스키마DB 관리자(DBA)전체 테이블, 관계, 제약조건. 보통 "스키마"라고 하면 이것
내부 스키마시스템실제 저장 방식: 파일, 인덱스, 블록 배치

외부와 개념 사이가 분리된 것을 논리적 독립성, 개념과 내부 사이가 분리된 것을 물리적 독립성이라 합니다.

1.3관계형 모델의 용어

테이블 = 릴레이션, 행 = 튜플, 열 = 속성. 같은 것을 부르는 이름이 셋씩 있습니다.

관계형 이론실무 용어파일 용어설명
릴레이션 (relation)테이블파일행과 열로 된 2차원 표
튜플 (tuple)행 (row)레코드한 건의 데이터. 학생 한 명
속성 (attribute)열 (column)필드데이터의 항목. 이름, 도시
카디널리티 (cardinality)행 수students의 카디널리티는 12
차수 (degree)열 수students의 차수는 6
도메인 (domain)자료형 + 허용 범위score는 0~100 사이 정수

릴레이션의 네 가지 성질

  • 튜플은 모두 다르다. 완전히 같은 행 두 개는 의미가 없으므로 기본키로 구분합니다.
  • 튜플에는 순서가 없다. 그래서 정렬이 필요하면 반드시 ORDER BY를 씁니다. 지금 보이는 순서는 우연입니다.
  • 속성에도 순서가 없다. 열은 이름으로 구분합니다.
  • 속성 값은 원자값이다. 한 칸에 "010-1111, 010-2222"처럼 여러 값을 넣지 않습니다(제1정규형).

1.4키(Key)의 종류

키는 행을 하나로 콕 집어내거나, 다른 테이블과 연결하는 열입니다.

키정의실습 데이터 예
슈퍼키행을 유일하게 구별할 수 있는 속성의 모든 조합 (유일성만 만족){student_id}, {student_id, name}, {phone, name}…
후보키슈퍼키 중 더 줄일 수 없는 것 (유일성 + 최소성){student_id}, {phone}(NULL이 없다면)
기본키 (PK)후보키 중 대표로 고른 하나. NULL 불가, 중복 불가students.student_id
대체키기본키로 뽑히지 않은 나머지 후보키phone
외래키 (FK)다른 테이블의 기본키를 참조하는 열enrollments.student_id → students.student_id
복합키두 개 이상의 열을 묶은 키(student_id, course_id)를 수강 테이블의 키로 쓸 경우
대리키 (인조키)의미 없는 일련번호를 일부러 만든 키enroll_id

무결성 제약조건

무결성규칙SQL로 거는 법
개체 무결성기본키는 NULL이나 중복을 가질 수 없다PRIMARY KEY
참조 무결성외래키 값은 참조하는 테이블에 실제 있는 값이거나 NULL이어야 한다FOREIGN KEY … REFERENCES
도메인 무결성속성 값은 정해진 범위 안에 있어야 한다자료형, CHECK, NOT NULL, DEFAULT
고유 무결성지정한 열은 중복될 수 없다UNIQUE
SQLD 포인트

기본키는 유일성과 최소성을 모두 만족하는 후보키 중 하나입니다. 슈퍼키는 유일성만 만족합니다. 외래키는 NULL을 가질 수 있지만 기본키는 가질 수 없습니다.

1.5SQL 문장의 분류

SQL은 하는 일에 따라 다섯 묶음으로 나뉩니다. 시험에는 거의 매번 나옵니다.

분류풀이명령어하는 일
DQLData Query LanguageSELECT데이터 조회 (DML에 포함하기도 함)
DMLData Manipulation LanguageINSERT UPDATE DELETE MERGE데이터 추가·수정·삭제
DDLData Definition LanguageCREATE ALTER DROP TRUNCATE RENAME테이블 같은 구조(객체) 정의
DCLData Control LanguageGRANT REVOKE권한 부여·회수
TCLTransaction Control LanguageCOMMIT ROLLBACK SAVEPOINT트랜잭션 확정·취소

SQL을 쓸 때의 기본 규칙

  • 키워드는 대소문자를 구분하지 않습니다. select와 SELECT는 같습니다. 이 노트는 읽기 쉽게 키워드를 대문자로 씁니다.
  • 문자열과 날짜는 작은따옴표로 감쌉니다. '부산'. 큰따옴표는 열 이름 같은 식별자용입니다(MySQL은 예외적으로 문자열에도 허용).
  • 문자열 값은 대소문자를 구분할 수 있습니다. Oracle은 'Kim'과 'kim'을 다르게 보고, MySQL은 기본 설정에서 같게 봅니다.
  • 문장 끝에는 세미콜론 ;을 붙입니다. 여러 문장을 한 번에 실행할 때 구분자가 됩니다.
  • 주석은 한 줄 -- 내용(대시 둘 뒤에 공백), 여러 줄 /* 내용 */. MySQL은 #도 됩니다.

SELECT, 데이터를 꺼내는 문장

실무 SQL의 대부분은 조회입니다. 열을 고르고, 행을 거르고, 정렬하고, 잘라내는 네 동작을 익힙니다.

3.1SELECT와 FROM

"어느 테이블에서(FROM) 어떤 열을(SELECT) 보여줘." 모든 조회의 뼈대입니다.

표준
SELECT 열1, 열2, …    -- 보여줄 열
FROM   테이블;          -- 가져올 곳
실행
SELECT name, city FROM students;

*는 모든 열입니다. 테이블을 처음 살펴볼 때는 편하지만, 실제 프로그램에서는 필요한 열만 적는 것이 좋습니다. 열이 추가되면 결과 모양이 바뀌고, 쓸데없는 데이터를 네트워크로 보내게 되기 때문입니다.

실행
SELECT * FROM instructors;

계산식과 별칭(AS)

SELECT에는 열뿐 아니라 계산식, 상수, 함수도 올 수 있습니다. AS로 결과 열에 이름을 붙입니다. AS는 생략할 수 있고, 별칭에 공백이나 특수문자가 있으면 큰따옴표로 감쌉니다.

실행
SELECT title,
       price,
       price * 0.9        AS 할인가,
       price / hours      AS "시간당 수강료",
       '원'               AS 단위
FROM courses;

문자열 붙이기

표준과 Oracle, SQLite는 ||, MySQL은 CONCAT() 함수를 씁니다. MySQL에서 ||는 기본 설정상 논리 OR입니다.

실행
SELECT name || ' (' || city || ')' AS 학생 FROM students;
MySQL
SELECT CONCAT(name, ' (', city, ')') AS 학생 FROM students;
SELECT CONCAT_WS('-', city, name) FROM students;   -- 구분자를 끼워 넣어 연결

DISTINCT, 중복 제거

결과에서 똑같은 행을 하나로 합칩니다. 여러 열에 쓰면 열 조합 전체가 같은 행만 합칩니다.

실행
SELECT DISTINCT city FROM students;
실행
SELECT DISTINCT category, instructor_id FROM courses;

FROM 없는 SELECT

실행
SELECT 1 + 2 AS 합, 'SQL' AS 문자, 10 / 3 AS 정수나눗셈, 10 / 3.0 AS 실수나눗셈;

SQLite와 MySQL은 FROM 없이 계산만 할 수 있습니다. Oracle은 22c 이전까지 FROM이 필수여서 FROM dual을 붙였고, 23ai부터는 생략해도 됩니다. 정수끼리 나누면 SQLite·PostgreSQL은 몫(3)만, MySQL·Oracle은 3.3333을 돌려줍니다.

NULL은 "모르는 값"

NULL은 0도 빈 문자열도 아닌, 값이 없음(알 수 없음)입니다. 그래서 NULL과의 비교는 참도 거짓도 아닌 UNKNOWN이 되고, WHERE는 UNKNOWN인 행을 버립니다. = NULL로는 절대 찾을 수 없고 반드시 IS NULL을 씁니다.

실행
SELECT name, phone FROM students WHERE phone = NULL;   -- 결과 0행 (잘못된 방법)
실행
SELECT name, phone FROM students WHERE phone IS NULL;  -- 올바른 방법

NOT IN과 NULL의 함정

x NOT IN (1, 2, NULL)은 x<>1 AND x<>2 AND x<>NULL이고, 마지막이 UNKNOWN이라 전체가 절대 참이 되지 않습니다. 목록이나 서브쿼리 결과에 NULL이 섞일 수 있으면 NOT IN 대신 NOT EXISTS를 쓰세요(5.2장).

실행

  • BETWEEN 1 AND 10은 >= 1 AND <= 10과 같습니다. 순서를 거꾸로(BETWEEN 10 AND 1) 쓰면 0행입니다.

3.3ORDER BY와 행 개수 제한

정렬은 ORDER BY, 위에서 몇 줄만 자르기는 DBMS마다 문법이 다릅니다.

  • NULL의 위치: Oracle·PostgreSQL은 NULL을 가장 큰 값으로 봐서 오름차순일 때 맨 뒤, MySQL·SQLite·SQL Server는 가장 작은 값으로 봐서 맨 앞에 둡니다. Oracle·PostgreSQL·SQLite는 NULLS FIRST / NULLS LAST로 직접 정할 수 있습니다.
실행

ORDER BY score DESC NULLS LAST;

SQL은 적는 순서와 실행 순서가 다릅니다. 이 순서를 알면 "별칭을 왜 WHERE에서 못 쓰지?" 같은 의문이 전부 풀립니다.

4.5CASE 식

SQL 안의 if문입니다. 값을 등급으로 나누고, 표시를 바꾸고, 조건부 집계를 만듭니다.

표준
-- 검색형 CASE: 조건을 위에서부터 검사, 처음 참인 THEN 값을 돌려줌
CASE WHEN 조건1 THEN 값1
     WHEN 조건2 THEN 값2
     ELSE 기본값          -- 생략하면 NULL
END

-- 단순형 CASE: 한 식의 값과 비교
CASE 식 WHEN 값1 THEN 결과1 WHEN 값2 THEN 결과2 ELSE 기본값 END
실행
SELECT student_id, score,
       CASE WHEN score >= 90 THEN 'A'
            WHEN score >= 80 THEN 'B'
            WHEN score >= 70 THEN 'C'
            WHEN score IS NULL THEN '진행중'
            ELSE 'F'
       END AS 등급
FROM enrollments ORDER BY score DESC;
실행
SELECT title,
       CASE category WHEN 'DB' THEN '데이터베이스'
                     WHEN '데이터' THEN '데이터 분석'
                     ELSE category END AS 분야
FROM courses;

Oracle에는 단순형 CASE를 함수로 쓴 DECODE(식, 값1, 결과1, 값2, 결과2, 기본값)가 있습니다. 오래된 코드에서 자주 보입니다. MySQL에는 조건이 하나일 때 쓰는 IF(조건, 참값, 거짓값)이 있습니다.

GROUP BY의 철칙

GROUP BY를 쓰면 SELECT에는 GROUP BY에 적은 열과 집계함수만 올 수 있습니다. 그룹 하나에 값이 여러 개인 열(예: 도시별로 묶었는데 이름)을 고르면 어떤 이름을 보여줄지 정할 수 없기 때문입니다. Oracle은 ORA-00979: not a GROUP BY expression 오류를 냅니다. MySQL(기본값 ONLY_FULL_GROUP_BY)도 막지만, SQLite는 아무 값이나 하나 보여주므로 착각하기 쉽습니다.

표준

HAVING: 그룹 거르기

WHERE는 그룹을 만들기 전 행을, HAVING은 그룹을 만든 후 그룹을 거릅니다. 집계함수 조건은 HAVING에만 쓸 수 있습니다.

실행
-- 수료한 기록만으로, 과정별 평균 점수가 80점 이상인 과정
SELECT course_id, COUNT(*) AS 수료인원, AVG(score) AS 평균
FROM enrollments
WHERE status = '수료'          -- 1) 행 거르기
GROUP BY course_id            -- 2) 묶기
HAVING AVG(score) >= 80        -- 3) 그룹 거르기
ORDER BY 평균 DESC;

조건부 집계: CASE + 집계

한 줄에 여러 조건의 개수를 나란히 세는 방법입니다. 리포트·대시보드 쿼리에서 가장 많이 쓰입니다.

실행
SELECT course_id,
       COUNT(*)                                             AS 전체,
       SUM(CASE WHEN status = '수료' THEN 1 ELSE 0 END)     AS 수료,
       SUM(CASE WHEN status = '수강중' THEN 1 ELSE 0 END)   AS 수강중,
       SUM(CASE WHEN status = '중도포기' THEN 1 ELSE 0 END) AS 포기,
       ROUND(100.0 * SUM(CASE WHEN status = '수료' THEN 1 ELSE 0 END) / COUNT(*), 1) AS 수료율
FROM enrollments
GROUP BY course_id;

이렇게 행을 열로 돌리는 것을 피벗(PIVOT)이라고 합니다. Oracle과 SQL Server에는 PIVOT 구문이 따로 있지만, CASE 방식은 모든 DBMS에서 통합니다.

Oracle
SELECT * FROM (SELECT course_id, status FROM enrollments)
PIVOT (COUNT(*) FOR status IN ('수료' AS 수료, '수강중' AS 수강중, '중도포기' AS 포기));

4.7ROLLUP, CUBE, GROUPING SETS

소계와 총계를 한 번에 붙입니다. SQLite에는 없어서 MySQL·Oracle 예제로 봅니다.

구문만드는 그룹지원
GROUP BY ROLLUP(A, B)(A,B), (A), () → 계층형 소계 + 총계. 순서 중요Oracle, MySQL(WITH ROLLUP), PostgreSQL, SQL Server
GROUP BY CUBE(A, B)(A,B), (A), (B), () → 가능한 모든 조합Oracle, PostgreSQL, SQL Server (MySQL 없음)
GROUP BY GROUPING SETS((A),(B))지정한 그룹만 (A), (B)Oracle, PostgreSQL, SQL Server (MySQL 없음)
GROUPING(A)그 행에서 A가 소계로 합쳐졌으면 1위와 같음, MySQL 8.0+
Oracle
SELECT category, instructor_id, SUM(price) AS 합계,
       GROUPING(category) AS g1, GROUPING(instructor_id) AS g2
FROM courses
GROUP BY ROLLUP(category, instructor_id)
ORDER BY category, instructor_id;
MySQL
SELECT category, instructor_id, SUM(price) AS 합계
FROM courses
GROUP BY category, instructor_id WITH ROLLUP;   -- 소계 행의 열은 NULL로 표시

SQLite나 ROLLUP이 없는 환경에서는 UNION ALL로 직접 합쳐 같은 결과를 만듭니다(5.3장).

실행
SELECT category, SUM(price) AS 합계 FROM courses GROUP BY category
UNION ALL
SELECT '총계', SUM(price) FROM courses;
SQLD 포인트
  • ROLLUP(A, B)는 그룹이 3개(A,B / A / 전체), CUBE(A, B)는 4개(A,B / A / B / 전체)입니다. 인수 n개일 때 ROLLUP은 n+1개, CUBE는 2ⁿ개.
  • ROLLUP은 인수 순서가 바뀌면 결과가 달라지고, CUBE와 GROUPING SETS는 순서와 무관합니다.
  • COUNT(*)와 COUNT(열)의 차이, 집계함수의 NULL 제외 규칙은 단골 문제입니다.

5.1JOIN, 테이블 합치기

두 테이블에서 연결 조건(보통 기본키 = 외래키)이 맞는 행끼리 옆으로 붙입니다.

수강 테이블에는 학생 번호만 있고 이름은 없습니다. 이름을 보려면 학생 테이블과 합쳐야 합니다.

실행
SELECT e.enroll_id, s.name, e.course_id, e.score
FROM enrollments e
JOIN students s ON e.student_id = s.student_id
ORDER BY e.enroll_id;
  • enrollments e처럼 테이블에 짧은 별칭을 붙이고 e.score처럼 씁니다. 두 테이블에 같은 이름의 열(student_id)이 있으면 반드시 어느 테이블 것인지 밝혀야 합니다.
  • JOIN은 INNER JOIN의 줄임입니다.
  • Oracle은 테이블 별칭에 AS를 쓰면 오류입니다. 별칭은 그냥 띄어 쓰세요.

ON과 WHERE의 차이 (LEFT JOIN에서만 중요)

ON의 조건은 "어떤 행끼리 짝지을지", WHERE의 조건은 "합친 뒤 무엇을 남길지"입니다. LEFT JOIN에서 오른쪽 테이블 조건을 WHERE에 쓰면 짝 없는 행(NULL)이 걸러져 사실상 INNER JOIN이 됩니다.

실행

SELECT s.name, e.course_id, e.status
FROM students s LEFT JOIN enrollments e
  ON s.student_id = e.student_id AND e.status = '수료'
WHERE s.student_id <= 4;
실행
-- WHERE에 조건: 수료 기록이 없는 학생이 사라짐
SELECT s.name, e.course_id, e.status
FROM students s LEFT JOIN enrollments e
  ON s.student_id = e.student_id
WHERE s.student_id <= 4 AND e.status = '수료';

USING, NATURAL JOIN

두 테이블의 연결 열 이름이 같으면 USING(열)으로 줄여 쓸 수 있습니다. NATURAL JOIN은 이름이 같은 모든 열로 자동 연결하는데, 우연히 같은 이름의 열(name 같은)이 있으면 엉뚱하게 합쳐지므로 실무에서는 쓰지 않습니다.

실행
SELECT student_id, s.name, e.course_id
FROM students s JOIN enrollments e USING (student_id)
WHERE student_id = 1;

예전 문법: WHERE 조인과 Oracle (+)

Oracle
-- 콤마 + WHERE 조인 (INNER와 같음)
SELECT s.name, e.score FROM students s, enrollments e
WHERE s.student_id = e.student_id;

-- Oracle 전용 외부조인: (+)는 "NULL로 채워질 쪽"에 붙인다
SELECT s.name, e.score FROM students s, enrollments e
WHERE s.student_id = e.student_id(+);   -- students 기준 LEFT JOIN
SQLD 포인트
  • CROSS JOIN 결과 행 수 = 두 테이블 행 수의 곱. 조인 조건을 빠뜨린 콤마 조인도 같은 결과(카티션 곱)가 됩니다.
  • Oracle (+)는 데이터가 없는 쪽(NULL이 채워질 쪽)에 붙습니다. A.id = B.id(+)는 A 기준 LEFT JOIN.
  • USING이나 NATURAL JOIN에서 연결 열 앞에는 테이블 별칭을 붙일 수 없습니다(Oracle 기준 오류).

안쪽 쿼리가 바깥 쿼리의 열(s.student_id)을 씁니다. EXISTS는 결과가 한 행이라도 있는지만 보고, 찾는 즉시 멈춥니다.

실행
-- 수강중인 과정이 있는 학생
SELECT s.name FROM students s
WHERE EXISTS (SELECT 1 FROM enrollments e
              WHERE e.student_id = s.student_id AND e.status = '수강중');
실행
-- 한 번도 수강하지 않은 학생 (NULL 걱정 없는 안티 조인)
SELECT s.name FROM students s
WHERE NOT EXISTS (SELECT 1 FROM enrollments e WHERE e.student_id = s.student_id);
실행
-- 자기 과정의 평균 점수보다 높은 수강 기록
SELECT e.enroll_id, e.course_id, e.score
FROM enrollments e
WHERE e.score > (SELECT AVG(x.score) FROM enrollments x WHERE x.course_id = e.course_id);

실행
SELECT c.title,
       (SELECT COUNT(*) FROM enrollments e WHERE e.course_id = c.course_id) AS 수강건수,
       (SELECT name FROM instructors i WHERE i.instructor_id = c.instructor_id) AS 강사
FROM courses c;

SELECT t.course_id, t.평균
FROM (SELECT course_id, AVG(score) AS 평균 FROM enrollments
      WHERE score IS NOT NULL GROUP BY course_id) t
WHERE t.평균 >= 85;
IN vs EXISTS vs JOIN

세 방법 모두 같은 결과를 낼 수 있는 경우가 많고, 최근 옵티마이저는 내부적으로 비슷하게 바꿔 실행합니다. 경험적인 기준: 결과에 상대 테이블 열이 필요하면 JOIN, 존재 여부만 보면 EXISTS, 작은 고정 목록이면 IN. 다만 NOT IN은 NULL 때문에 결과가 틀어질 수 있어 NOT EXISTS를 쓰는 것이 안전합니다.

SQLD 포인트
  • 단일행 연산자(=, <, >) 뒤의 서브쿼리가 2행 이상 돌려주면 오류(Oracle ORA-01427).
  • 서브쿼리 안에서는 ORDER BY를 쓰지 않습니다(인라인 뷰 제외, Oracle은 일반 서브쿼리 ORDER BY가 오류).
  • 메인 쿼리는 서브쿼리 열을 직접 쓸 수 없고, 서브쿼리는 메인 쿼리 열을 쓸 수 있습니다(상관).

5.3집합 연산

JOIN이 옆으로 붙인다면, 집합 연산은 결과를 위아래로 쌓습니다.

연산결과참고
UNION합집합, 중복 제거중복 제거를 위해 정렬이 일어나 느릴 수 있음
UNION ALL합집합, 중복 그대로가장 빠름. 중복이 없거나 상관없으면 이것
INTERSECT교집합MySQL 8.0.31부터 지원
EXCEPT / MINUS차집합 (앞 − 뒤)표준·SQLite·PostgreSQL·MySQL 8.0.31+는 EXCEPT, Oracle은 MINUS(21c+는 EXCEPT도)

규칙: 위아래 SELECT의 열 개수가 같고 대응하는 열의 자료형이 호환되어야 합니다. 결과 열 이름은 첫 번째 SELECT를 따르고, ORDER BY는 맨 마지막에 한 번만 씁니다.

실행
-- 학생과 강사 이름을 한 목록으로
SELECT name, '학생' AS 구분 FROM students WHERE city = '서울'
UNION ALL
SELECT name, '강사' FROM instructors
ORDER BY 구분, name;
실행
-- 101번 과정을 듣고 102번 과정도 들은 학생
SELECT student_id FROM enrollments WHERE course_id = 101
INTERSECT
SELECT student_id FROM enrollments WHERE course_id = 102;
실행
-- 101번은 들었지만 102번은 안 들은 학생
SELECT student_id FROM enrollments WHERE course_id = 101
EXCEPT
SELECT student_id FROM enrollments WHERE course_id = 102;
MySQL
-- MySQL의 FULL OUTER JOIN 대용
SELECT s.name, e.course_id FROM students s LEFT JOIN enrollments e ON s.student_id = e.student_id
UNION
SELECT s.name, e.course_id FROM students s RIGHT JOIN enrollments e ON s.student_id = e.student_id;
SQLD 포인트

UNION과 UNION ALL의 결과 행 수 차이를 묻는 문제가 자주 나옵니다. UNION은 결과 전체에서 중복을 제거하므로, 한쪽 SELECT 안에 있던 중복도 함께 사라집니다.

윈도우 함수와 CTE

순위, 누적합, 전월 대비, 그룹별 상위 N개, 조직도 펼치기. 실무 리포트와 코딩 테스트에서 자주 만나는 문제들입니다.

6.1윈도우 함수

GROUP BY는 행을 줄여 요약하고, 윈도우 함수는 행을 그대로 둔 채 옆에 요약값을 붙입니다.

표준
함수() OVER (
  PARTITION BY 그룹열     -- 어떤 묶음 안에서 계산할지 (생략하면 전체)
  ORDER BY 정렬열         -- 묶음 안의 순서
  ROWS BETWEEN … AND …  -- 계산 범위 (프레임)
)

MySQL 8.0, Oracle, PostgreSQL, SQL Server, SQLite 3.25 이상에서 모두 지원합니다. MySQL 5.7에는 없습니다.

순위 함수

실행
SELECT student_id, course_id, score,
       ROW_NUMBER() OVER (ORDER BY score DESC) AS row_num,
       RANK()       OVER (ORDER BY score DESC) AS rnk,
       DENSE_RANK() OVER (ORDER BY score DESC) AS dense
FROM enrollments
WHERE course_id IN (101, 102) AND score IS NOT NULL;
함수동점 처리점수 99, 97, 97, 92일 때
ROW_NUMBER()동점이어도 다른 번호1, 2, 3, 4
RANK()동점은 같은 순위, 다음 순위는 건너뜀1, 2, 2, 4
DENSE_RANK()동점은 같은 순위, 건너뛰지 않음1, 2, 2, 3
NTILE(n)n개 구간으로 균등 분할NTILE(2) → 1, 1, 2, 2
PERCENT_RANK() CUME_DIST()백분위 순위, 누적 분포0~1 사이 값
실행
-- 과정 안에서의 순위 (PARTITION BY)
SELECT course_id, student_id, score,
       RANK() OVER (PARTITION BY course_id ORDER BY score DESC) AS 과정내순위
FROM enrollments
WHERE score IS NOT NULL
ORDER BY course_id, 과정내순위;

집계 윈도우: 전체 대비, 누적, 이동 평균

실행
SELECT name, dept, salary,
       SUM(salary) OVER ()                       AS 전체합,
       AVG(salary) OVER (PARTITION BY dept)      AS 부서평균,
       salary - AVG(salary) OVER (PARTITION BY dept) AS 평균대비,
       ROUND(100.0 * salary / SUM(salary) OVER (PARTITION BY dept), 1) AS 부서내비중
FROM employees
ORDER BY dept, salary DESC;
실행
-- 월별 신청 건수와 누적 건수
SELECT 월, 건수,
       SUM(건수) OVER (ORDER BY 월) AS 누적,
       ROUND(AVG(건수) OVER (ORDER BY 월 ROWS BETWEEN 2 PRECEDING AND CURRENT ROW), 1) AS 최근3개월평균
FROM (SELECT STRFTIME('%Y-%m', enrolled_at) AS 월, COUNT(*) AS 건수
      FROM enrollments GROUP BY 1) t;
프레임 지정뜻
ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW처음부터 현재 행까지 (누적)
ROWS BETWEEN 2 PRECEDING AND CURRENT ROW앞 2행 + 현재 행 (3행 이동)
ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING앞뒤 한 행씩
ROWS BETWEEN CURRENT ROW AND UNBOUNDED FOLLOWING현재부터 끝까지
RANGE …행 개수가 아닌 값 기준. ORDER BY 값이 같은 행을 한 덩어리로 봄

ORDER BY만 쓰고 프레임을 생략하면 기본값은 RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW입니다. 그래서 정렬 값이 같은 행들은 누적합이 한꺼번에 같은 값으로 뜁니다.

앞뒤 행 참조: LAG, LEAD, FIRST_VALUE

실행
SELECT student_id, enrolled_at, course_id,
       LAG(course_id)  OVER (PARTITION BY student_id ORDER BY enrolled_at) AS 이전과정,
       LEAD(enrolled_at) OVER (PARTITION BY student_id ORDER BY enrolled_at) AS 다음신청일,
       FIRST_VALUE(course_id) OVER (PARTITION BY student_id ORDER BY enrolled_at) AS 첫과정
FROM enrollments
WHERE student_id IN (1, 2, 3)
ORDER BY student_id, enrolled_at;

LAG(열, n, 기본값)은 n행 앞의 값을, LEAD는 n행 뒤의 값을 가져옵니다. 전월 대비 증감, 재방문 간격 계산에 씁니다. LAST_VALUE는 기본 프레임이 현재 행까지라 "현재 행"이 나오기 쉬우니, ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING을 함께 쓰세요.

그룹별 상위 N개 (가장 자주 묻는 패턴)

실행
-- 과정마다 점수 1등만
SELECT course_id, student_id, score FROM (
  SELECT course_id, student_id, score,
         ROW_NUMBER() OVER (PARTITION BY course_id ORDER BY score DESC) AS rn
  FROM enrollments WHERE score IS NOT NULL
) t
WHERE rn = 1;

윈도우 함수는 SELECT 단계에서 계산되므로 같은 쿼리의 WHERE에 쓸 수 없습니다. 인라인 뷰나 CTE로 한 번 감싸야 합니다. Snowflake·BigQuery 같은 일부 분석용 DB에는 이를 한 번에 거르는 QUALIFY 절이 있지만 MySQL·Oracle·PostgreSQL에는 없으므로, 감싸는 방식이 어디서나 통합니다.

SQLD 포인트
  • RANK / DENSE_RANK / ROW_NUMBER의 동점 결과 차이는 거의 매회 출제.
  • 윈도우 함수는 결과 행 수를 줄이지 않는다. GROUP BY와의 차이.
  • 프레임 생략 시 기본값(RANGE UNBOUNDED PRECEDING ~ CURRENT ROW)과 ROWS/RANGE 차이.

6.2WITH절 (CTE)

긴 서브쿼리에 이름을 붙여 위에 먼저 정의해 둡니다. 쿼리를 위에서 아래로 읽히게 만듭니다.

실행
WITH 과정통계 AS (
  SELECT course_id, COUNT(*) AS 건수, AVG(score) AS 평균
  FROM enrollments GROUP BY course_id
),
인기과정 AS (
  SELECT * FROM 과정통계 WHERE 건수 >= 4
)
SELECT c.title, p.건수, ROUND(p.평균, 1) AS 평균
FROM 인기과정 p JOIN courses c ON c.course_id = p.course_id
ORDER BY p.건수 DESC;
  • CTE(Common Table Expression)는 그 쿼리 안에서만 존재하는 이름 붙은 결과입니다.
  • 여러 개를 쉼표로 이어 정의하고, 뒤의 CTE가 앞의 CTE를 쓸 수 있습니다.
  • MySQL 8.0, Oracle, PostgreSQL, SQL Server, SQLite에서 지원합니다.

6.3재귀 쿼리와 계층 구조

조직도, 카테고리 트리, 댓글의 답글처럼 자기 자신을 가리키는 데이터를 끝까지 펼칩니다.

실행
WITH RECURSIVE org AS (
  -- 시작점: 상사가 없는 대표
  SELECT emp_id, name, manager_id, 1 AS 단계, name AS 경로
  FROM employees WHERE manager_id IS NULL
  UNION ALL
  -- 반복: 지금까지 찾은 사람의 부하 직원
  SELECT e.emp_id, e.name, e.manager_id, o.단계 + 1, o.경로 || ' > ' || e.name
  FROM employees e JOIN org o ON e.manager_id = o.emp_id
)
SELECT 단계, name, 경로 FROM org ORDER BY 경로;

재귀 CTE는 시작 쿼리와 반복 쿼리를 UNION ALL로 잇고, 반복 쿼리가 더 이상 새 행을 만들지 않으면 멈춥니다. Oracle은 WITH 뒤에 RECURSIVE를 쓰지 않고, 대신 전용 문법 CONNECT BY를 오래 써 왔습니다.

Oracle
SELECT LEVEL AS 단계,
       LPAD(' ', (LEVEL - 1) * 2) || name AS 조직도,
       SYS_CONNECT_BY_PATH(name, ' > ')   AS 경로,
       CONNECT_BY_ISLEAF                  AS 말단여부
FROM employees
START WITH manager_id IS NULL          -- 시작 행
CONNECT BY PRIOR emp_id = manager_id   -- 부모의 emp_id = 자식의 manager_id
ORDER SIBLINGS BY name;                -- 같은 단계끼리 정렬
실행
-- 재귀로 숫자·날짜 만들기: 2026년 3월~8월 달력 뼈대
WITH RECURSIVE months(m) AS (
  SELECT '2026-03-01'
  UNION ALL
  SELECT DATE(m, '+1 month') FROM months WHERE m < '2026-08-01'
)
SELECT STRFTIME('%Y-%m', m) AS 월,

M:N 관계는 테이블로 바로 만들 수 없습니다. 학생 한 명이 여러 과정을, 과정 하나를 여러 학생이 들으므로, 그 사이에 수강(enrollments)이라는 교차 엔터티를 두어 1:N 두 개로 풉니다. 실습 데이터가 바로 이 구조입니다.

  • 비식별 관계: 부모의 기본키가 자식의 일반 열(외래키)로만 감. 예) 과정의 instructor_id. 점선.
  • 식별 관계를 길게 이으면 손자·증손 테이블의 PK가 계속 길어지므로, 실무에서는 대리키(enroll_id)를 두고 비식별로 끊는 경우가 많습니다.

인덱스, 튜닝, 프로그램과 SQL

데이터가 수백만 건이 되면 같은 결과를 내는 쿼리도 1초와 1분으로 갈립니다. 그리고 SQL은 결국 프로그램 안에서 실행됩니다.

9.1인덱스의 원리

인덱스는 열 값을 정렬해 둔 별도의 구조(주로 B-Tree)입니다. 전체를 훑지 않고 몇 번만 내려가면 원하는 행을 찾습니다.

  • 인덱스가 없으면 테이블 전체를 처음부터 끝까지 읽습니다(Full Table Scan).
  • 인덱스는 조회는 빠르게, INSERT·UPDATE·DELETE는 느리게 합니다. 데이터가 바뀔 때마다 인덱스도 고쳐야 하기 때문입니다. 아무 열에나 만들지 않습니다.
  • 기본키와 UNIQUE 제약에는 인덱스가 자동으로 생깁니다. MySQL InnoDB는 외래키에도 자동으로 만듭니다(Oracle은 안 만들어 주므로 직접 만드는 것이 좋습니다).
  • MySQL InnoDB의 테이블은 기본키 순서로 저장됩니다(클러스터드 인덱스). 그래서 기본키는 짧고 순서대로 증가하는 값이 유리합니다.

복합 인덱스의 열 순서

복합 인덱스 (A, B)는 전화번호부처럼 "A로 정렬하고, A가 같으면 B로 정렬"한 것입니다. 그래서 A만으로도, A와 B로도 찾을 수 있지만 B만으로는 못 찾습니다. 순서는 보통 등호(=) 조건 열을 앞에, 범위(>, BETWEEN) 조건 열을 뒤에 둡니다.

커버링 인덱스

방식동작유리할 때

Hash Join작은 쪽으로 해시 테이블을 만들고 큰 쪽을 대조대용량끼리 등가 조인. 인덱스 없어도 빠름 (MySQL 8.0.18+)

실무 튜닝 체크리스트

  1. 필요한 열만 SELECT. SELECT * 금지.
  2. WHERE의 열은 가공하지 말고 상수 쪽을 가공.
  3. 자주 거르는 열, JOIN 열, ORDER BY 열에 인덱스. 단, 값 종류가 적은 열(성별)은 효과가 작음.
  4. 중복 제거가 필요 없으면 UNION 대신 UNION ALL, DISTINCT 남발 금지.
  5. 큰 테이블의 OFFSET 페이지 이동은 뒤로 갈수록 느림. 마지막으로 본 키 기준(WHERE id > 마지막id LIMIT 20)으로 넘기기.
  6. 반복문 안에서 쿼리를 1건씩 날리지 말고 한 번에 처리(N+1 문제).
  7. 통계 정보를 최신으로: MySQL ANALYZE TABLE, Oracle DBMS_STATS.GATHER_TABLE_STATS.
  8. 추측하지 말고 실행계획과 실제 실행 시간으로 확인.
SQLD 포인트
  • 옵티마이저: 규칙 기반(RBO, 우선순위 규칙) vs 비용 기반(CBO, 통계로 비용 계산). 현재는 CBO가 기본.
  • NL 조인은 랜덤 액세스, 소량·인덱스 유리 / 해시 조인은 등가 조인만, 대량 유리 / 소트 머지는 정렬 필요, 비등가 가능.
  • 인덱스 선두 열이 조건에 없으면 인덱스 범위 스캔 불가(Oracle은 인덱스 스킵 스캔으로 쓰는 경우 있음).

DELIMITER //       -- 프로시저 안의 ; 와 구분하려고 문장 끝 기호를 잠시 바꿈
CREATE PROCEDURE enroll_student(IN p_student INT, IN p_course INT, OUT p_result VARCHAR(50))
BEGIN
  DECLARE v_cnt INT;
  SELECT COUNT(*) INTO v_cnt FROM enrollments
  WHERE student_id = p_student AND course_id = p_course AND status = '수강중';

  IF v_cnt > 0 THEN
    SET p_result = '이미 수강중인 과정';
  ELSE
    INSERT INTO enrollments (student_id, course_id, enrolled_at, status)
    VALUES (p_student, p_course, CURDATE(), '수강중');
    SET p_result = '등록 완료';
  END IF;
END //
DELIMITER ;

CALL enroll_student(4, 102, @msg);
SELECT @msg;

10.1종합 문제

실무 요청처럼 문장으로 주어집니다. 어떤 테이블이 필요한지부터 생각해 보세요. 실행 전 실습 DB 초기화를 한 번 눌러 두면 정답 결과와 똑같이 나옵니다.

F-1"부산 거주 학생 중 수료한 과정이 2개 이상인 학생 명단을 이름순으로 뽑아 주세요."중

정답과 해설
실행
SELECT s.name, COUNT(*) AS 수료과정수
FROM students s JOIN enrollments e ON s.student_id = e.student_id
WHERE s.city = '부산' AND e.status = '수료'
GROUP BY s.student_id, s.name
HAVING COUNT(*) >= 2
ORDER BY s.name;

행 조건(부산, 수료)은 WHERE, 그룹 조건(2개 이상)은 HAVING. GROUP BY에 student_id를 함께 넣어 동명이인을 구분합니다.

F-2"과정별로 수강 신청 건수, 수료율(%), 평균 점수를 보여주되, 신청이 없는 과정도 0으로 나오게 해 주세요."상

정답과 해설
실행
SELECT c.title,
       COUNT(e.enroll_id) AS 신청건수,
       ROUND(100.0 * SUM(CASE WHEN e.status = '수료' THEN 1 ELSE 0 END) / NULLIF(COUNT(e.enroll_id), 0), 1) AS 수료율,
       ROUND(AVG(e.score), 1) AS 평균점수
FROM courses c
LEFT JOIN enrollments e ON c.course_id = e.course_id
GROUP BY c.course_id, c.title
ORDER BY 신청건수 DESC;

LEFT JOIN으로 신청 없는 과정을 살리고, COUNT는 오른쪽 열을 셉니다. 신청이 0건이면 나눗셈 분모가 0이 되므로 NULLIF로 막았습니다.

F-3"강사별로 담당 과정의 수료생 평균 점수를 구하고, 전체 강사 중 몇 등인지 붙여 주세요."상

정답과 해설
실행
WITH t AS (
  SELECT i.name AS 강사, ROUND(AVG(e.score), 1) AS 평균
  FROM instructors i
  JOIN courses c     ON c.instructor_id = i.instructor_id
  JOIN enrollments e ON e.course_id = c.course_id
  WHERE e.status = '수료'
  GROUP BY i.instructor_id, i.name
)
SELECT 강사, 평균, RANK() OVER (ORDER BY 평균 DESC) AS 순위 FROM t;

집계 결과에 다시 순위를 매기려면 CTE로 집계를 먼저 만들고 바깥에서 윈도우 함수를 씁니다. 사실 RANK() OVER (ORDER BY AVG(e.score) DESC)처럼 한 쿼리에 써도 됩니다. 윈도우 함수는 GROUP BY 이후에 계산되기 때문입니다.

F-4"SQL 기초(101)를 수료한 학생 중 아직 SQL 활용과 튜닝(102)을 신청하지 않은 사람에게 안내 문자를 보내려고 합니다. 이름과 연락처를 뽑아 주세요. 연락처가 없으면 제외합니다."중

정답과 해설
실행
SELECT s.name, s.phone
FROM students s
WHERE s.phone IS NOT NULL
  AND EXISTS (SELECT 1 FROM enrollments e
              WHERE e.student_id = s.student_id AND e.course_id = 101 AND e.status = '수료')
  AND NOT EXISTS (SELECT 1 FROM enrollments e
                  WHERE e.student_id = s.student_id AND e.course_id = 102);

"했다"는 EXISTS, "안 했다"는 NOT EXISTS. 상담·마케팅 대상자 추출 쿼리의 전형입니다.

F-5"월별 신규 등록 학생 수와 전월 대비 증감을 보여주세요."상

정답과 해설
실행
WITH m AS (
  SELECT STRFTIME('%Y-%m', joined_at) AS 월, COUNT(*) AS 신규
  FROM students GROUP BY 1
)
SELECT 월, 신규,
       신규 - LAG(신규) OVER (ORDER BY 월) AS 전월대비
FROM m ORDER BY 월;

F-6"분류(category)마다 수강료가 가장 비싼 과정의 이름과 수강료를 보여주세요. 동점이면 모두 보여주세요."중

정답과 해설
실행
SELECT category, title, price FROM (
  SELECT category, title, price,
         RANK() OVER (PARTITION BY category ORDER BY price DESC) AS r
  FROM courses) t
WHERE r = 1
ORDER BY price DESC;

F-7"직원마다 자기 아래에 있는 모든 부하(직속 + 그 아래) 수를 구해 주세요."최상

정답과 해설
실행
WITH RECURSIVE sub(boss, member) AS (
  SELECT manager_id, emp_id FROM employees WHERE manager_id IS NOT NULL
  UNION ALL
  SELECT s.boss, e.emp_id FROM sub s JOIN employees e ON e.manager_id = s.member
)
SELECT e.name, COUNT(s.member) AS 전체부하수
FROM employees e LEFT JOIN sub s ON s.boss = e.emp_id
GROUP BY e.emp_id, e.name
ORDER BY 전체부하수 DESC, e.emp_id;

10.6SQLD 한 장 요약과 다음 단계

과목자주 나오는 것이 노트
1과목 데이터 모델링의 이해모델링 3단계, 엔터티·속성·관계·식별자, 정규화, 반정규화, 성능 모델링, 분산 DB1.3, 1.4, 8장
2과목 SQL 기본 및 활용실행 순서, NULL 연산, 집계·GROUP BY·HAVING, JOIN 종류, 서브쿼리, 집합 연산, 그룹 함수(ROLLUP·CUBE), 윈도우 함수, 계층 쿼리, DCL·TCL3~7장

SQLD는 Oracle 문법을 기준으로 출제되는 경우가 많습니다. ROWNUM, NVL, DECODE, CONNECT BY, MINUS 같은 Oracle 전용 문법을 꼭 따로 익히세요. 출제 범위는 개편될 수 있으니 응시 전 한국데이터산업진흥원 데이터자격검정 사이트에서 최신 출제 기준을 확인하세요.

다음에 공부할 것

  • SQLP·DAP: SQL 전문가·데이터 아키텍처 전문가. 튜닝과 설계를 깊게 다룹니다.
  • 정보처리기사 실기: SQL 작성 문제와 관계대수(σ 선택, π 프로젝션, ⋈ 조인)가 출제됩니다.
  • 백엔드 개발: JDBC → MyBatis → JPA 순서로 프로그램에서 DB 다루기.
  • 데이터 분석: 윈도우 함수와 CTE를 깊게, 그리고 pandas와 SQL을 함께.
  • 코딩 테스트 SQL: 프로그래머스 SQL 고득점 Kit, LeetCode Database 문제로 꾸준히 연습.
