Part 1

준비

자바가 어떤 언어인지 알고, 내 컴퓨터에 JDK를 깔고, VS Code와 Jupyter에서 첫 코드를 돌려 봅니다.

0

자바는 어떤 언어인가

코드를 한 번 번역해 두면 어느 컴퓨터에서든 그대로 돌아가는 언어. 이 한 줄이 자바의 거의 전부다.

0-1. 번역해 두고 실행한다

컴퓨터는 사람이 쓴 글자를 바로 알아듣지 못한다. 그래서 중간에 번역이 필요하다. 자바는 이 번역을 두 단계로 나눈다.

  1. 내가 Hello.java를 쓴다. 사람이 읽을 수 있는 영어 비슷한 글이다.

  2. javac가 Hello.class로 번역한다. 이 결과물을 바이트코드라고 부른다. 사람은 못 읽고, 아직 특정 컴퓨터 전용도 아니다.

  3. java가 JVM을 띄워 Hello.class를 실행한다. JVM(자바 가상 머신)이 바이트코드를 그 컴퓨터가 알아듣는 말로 바꿔 가며 돌린다.

윈도우용 JVM, 맥용 JVM, 리눅스용 JVM이 따로 있고, .class 파일은 하나다. 그래서 회사 서버가 리눅스든 내 노트북이 윈도우든 같은 파일이 그대로 돈다. 맨 위 그림이 이 과정이다.

Hello.java
public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello, Java");
    }
}
실행 결과
Hello, Java

지금은 이 다섯 줄이 무슨 뜻인지 몰라도 된다. 4장에서 한 줄씩 뜯어본다. 지금 기억할 건 하나다. 자바 프로그램은 반드시 클래스 안에 있고, 실행은 main에서 시작한다.

0-2. JDK, JRE, JVM

설치하다 보면 이 세 단어가 계속 나온다. 큰 상자 안에 작은 상자가 들어 있는 관계다.

0-3. 파이썬을 조금 해 봤다면

파이썬을 먼저 배운 사람이 자바에서 처음 걸리는 지점은 거의 정해져 있다.

항목파이썬자바
변수 만들기age = 27int age = 27; 자료형을 먼저 적는다
문장 끝줄바꿈세미콜론 ;
블록들여쓰기중괄호 { }. 들여쓰기는 보기 좋으라고 하는 것
실행 시작점파일 맨 위부터main 메서드부터
오류 발견실행하다가 그 줄에서대부분 번역(컴파일) 단계에서 미리

마지막 줄이 중요하다. 자바는 깐깐하다. 자료형이 안 맞으면 아예 번역을 안 해 준다. 처음엔 귀찮지만, 프로그램이 커질수록 "돌려 보기 전에 잡히는 실수"가 많다는 게 얼마나 편한지 알게 된다. 은행, 공공기관, 대기업 전산 시스템에 자바가 많은 이유 중 하나다.

0-4. 어떤 버전을 쓰나

자바는 6개월마다 새 버전이 나오고, 그중 몇 개를 LTS(장기 지원) 버전으로 정해 오래 관리한다. 회사들은 거의 LTS만 쓴다. 지금 최신 버전은 JDK 27이고, 최신 LTS는 JDK 25다. 이 교재는 JDK 25 기준이다. 이 교재의 예제는 JDK 21 이상이면 전부 똑같이 돈다.

1

JDK 설치하기

윈도우 기준으로 설명하고, 맥은 따로 짧게 정리했다. 설치 자체는 5분, 환경 변수까지 해도 15분이면 끝난다.

1-1. 내려받기

  1. 오라클 자바 다운로드 페이지(oracle.com/java/technologies/downloads)에 들어간다. 검색창에 "Oracle JDK download"를 쳐도 맨 위에 나온다.

  2. 위쪽 버전 탭에서 JDK 25를 고른다. 맨 앞에 보이는 JDK 27은 최신이지만 LTS가 아니다.

  3. 운영체제 탭에서 Windows를 고르고, 목록에서 x64 Installer(.exe)를 받는다. 오라클 계정 로그인 없이 바로 받아진다.

  4. 받은 파일을 실행하고 다음만 계속 누른다. 설치 경로 화면에서 경로를 한 번 봐 둔다. 보통 C:\Program Files\Java\jdk-25이다.

1-2. 설치 확인

윈도우 검색에서 cmd를 쳐서 명령 프롬프트를 연다. 설치하기 전에 열어 둔 창이 있다면 닫고 새로 연다. 창은 열리는 순간의 설정을 기억하기 때문이다.

터미널
C:\Users\me>java -version
# 첫 줄에 java version "25.0.숫자" 와 LTS 가 보이면 성공

C:\Users\me>javac -version
# javac 25.0.숫자 가 보이면 번역기까지 준비 끝

둘 다 버전이 나오면 설치는 성공이다. 그래도 다음 절의 JAVA_HOME은 꼭 만들어 두자. 설치 프로그램이 java 명령은 잡아 주지만, VS Code나 Jupyter 같은 도구는 JAVA_HOME을 보고 JDK를 찾는 경우가 많다.

1-3. 환경 변수 JAVA_HOME과 Path

환경 변수는 "이 컴퓨터에서 자바는 어디 있다"고 적어 둔 메모다. 두 개를 손본다.

  1. 윈도우 검색에서 시스템 환경 변수 편집을 연다. 창 아래쪽 환경 변수 버튼을 누른다.

  2. 아래쪽 시스템 변수 칸에서 새로 만들기. 변수 이름 JAVA_HOME, 변수 값 C:\Program Files\Java\jdk-25. 값은 bin 앞까지만 적는다.

  3. 같은 칸에서 Path를 골라 편집 → 새로 만들기 → %JAVA_HOME%\bin을 적는다. 오른쪽 위로 이동을 눌러 맨 위로 올린다. 다른 자바가 깔려 있어도 이게 먼저 쓰이게 하려는 것이다.

  4. 확인을 세 번 눌러 창을 다 닫고, cmd를 새로 열어 확인한다.

터미널
C:\Users\me>echo %JAVA_HOME%
C:\Program Files\Java\jdk-25

C:\Users\me>where java
C:\Program Files\Java\jdk-25\bin\java.exe
자주 하는 실수

'javac'은(는) 내부 또는 외부 명령... 이 아닙니다가 뜨면 Path가 안 잡힌 것이다. Path에 %JAVA_HOME%\bin이 있는지, JAVA_HOME 값 끝에 \bin을 또 붙이지 않았는지(...\bin\bin이 되어 버린다), cmd를 새로 열었는지 순서대로 확인한다.

1-4. 맥이라면

같은 다운로드 페이지에서 macOS 탭을 고른다. 애플 메뉴 → 이 Mac에 관하여에서 칩을 확인하고, Apple M 계열이면 ARM64 DMG Installer, 인텔이면 x64 DMG Installer를 받는다. 설치 후 터미널에서 아래처럼 JAVA_HOME을 등록한다.

터미널
$ /usr/libexec/java_home -V
# 설치된 JDK 목록이 나온다
$ echo 'export JAVA_HOME=$(/usr/libexec/java_home -v 25)' >> ~/.zshrc
$ source ~/.zshrc
$ java -version

1-5. 메모장으로 첫 번역

도구 없이 한 번은 손으로 해 보는 게 좋다. 이걸 해 봐야 VS Code의 실행 버튼이 뒤에서 뭘 하는지 안다.

  1. C:\java 폴더를 만든다.

  2. 메모장에 0장의 Hello 코드를 그대로 적고, 파일 형식: 모든 파일, 인코딩 UTF-8로 C:\java\Hello.java에 저장한다.

  3. cmd에서 아래처럼 번역하고 실행한다.

터미널
C:\Users\me>cd C:\java
C:\java>javac Hello.java
C:\java>dir /b
Hello.class
Hello.java
C:\java>java Hello
Hello, Java

javac Hello.java는 파일 이름이라 .java까지 쓰고, java Hello는 클래스 이름이라 .class를 안 쓴다. 처음엔 다들 한 번씩 반대로 친다. 파일 하나짜리 연습 코드라면 번역과 실행을 한 번에 해 주는 방법도 있다.

터미널
C:\java>java Hello.java
Hello, Java
# 번역과 실행을 한 번에. 파일 하나짜리 연습용으로 편하다
자주 하는 실수

class Hello is public, should be declared in a file named Hello.java는 파일 이름과 클래스 이름이 다를 때 나온다. 대소문자까지 같아야 한다. 메모장이 몰래 Hello.java.txt로 저장하는 경우도 있으니, 탐색기 보기 메뉴에서 파일 확장명을 켜 두자.

2

VS Code로 자바 쓰기

앞으로 코드는 전부 여기서 쓴다. 자동 완성, 오류 밑줄, 실행 버튼, 한 줄씩 따라가는 디버거까지 한 화면에 있다.

2-1. 설치와 자바 확장

  1. code.visualstudio.com에서 내려받아 설치한다. 설치 중 추가 작업 선택 화면에서 "Code(으)로 열기" 작업을 탐색기 메뉴에 추가와 PATH에 추가를 체크해 두면 편하다.

  2. 왼쪽 막대의 블록 네 개 모양 아이콘(확장, Ctrl+Shift+X)을 누르고 Extension Pack for Java를 검색해 설치한다. 만든 곳이 Microsoft인지 확인한다. 자바 언어 지원, 디버거, 프로젝트 관리 도구가 한 번에 깔린다.

  3. 메뉴를 한글로 보고 싶으면 Korean Language Pack도 설치하고 VS Code를 다시 켠다. 이 교재는 한글 메뉴 기준이다.

  4. Ctrl+Shift+P로 명령 팔레트를 열고 Java: Configure Java Runtime을 실행한다. 목록에 JDK 25가 보이면 VS Code가 JDK를 찾은 것이다. 안 보이면 1-3의 JAVA_HOME부터 다시 본다.

2-2. 프로젝트 만들기

자바는 파일 하나보다 프로젝트(폴더) 단위로 다루는 게 기본이다.

  1. Ctrl+Shift+P → Java: Create Java Project.

  2. 빌드 도구를 묻는 목록에서 No build tools를 고른다. Maven, Gradle은 나중에 큰 프로젝트를 할 때 쓰는 것이다.

  3. 프로젝트를 둘 폴더를 고르고, 프로젝트 이름(예: study-java)을 적는다.

프로젝트 구조
study-java/
├─ .vscode/        VS Code 설정 (건드릴 일 거의 없음)
├─ bin/            javac가 만든 .class 파일이 쌓이는 곳
├─ lib/            외부 라이브러리 .jar 를 넣는 곳 (18장에서 사용)
└─ src/
   └─ App.java     여기서부터 코드를 쓴다
App.java
public class App {
    public static void main(String[] args) throws Exception {
        System.out.println("Hello, World!");
    }
}

VS Code가 만들어 준 App.java다. throws Exception은 15장에서 배운다. 지금은 있어도 없어도 상관없다.

2-3. 실행과 디버깅

main 줄 바로 위에 작은 글씨로 Run | Debug가 보인다. Run을 누르면 아래 터미널 창에 결과가 나온다. 오른쪽 위의 재생 모양 버튼도 같은 일을 한다. 이 버튼이 하는 일이 1-5에서 손으로 친 javac와 java 두 줄이다.

디버깅은 코드를 한 줄씩 멈춰 가며 변수 값을 보는 기능이다. 줄 번호 왼쪽을 클릭하면 빨간 점(중단점)이 생긴다. Debug로 실행하면 그 줄에서 멈추고, 왼쪽 변수 칸에 지금 값이 보인다. F10을 누를 때마다 한 줄씩 진행한다. 9장 반복문에서 머리로 따라가기 힘들 때 이걸 쓰면 된다.

메모

한 프로젝트 안에 연습 파일을 여러 개 만들어도 된다. src에서 오른쪽 클릭 → 새 파일 → Ex04.java처럼 만들고, 안에 public class Ex04를 쓴다. 파일 이름과 public 클래스 이름은 언제나 같아야 한다. 각 파일에 main이 있으면 각자 따로 실행된다.

3

Anaconda와 Jupyter로 자바 쓰기

문법 하나 시험해 보려고 클래스를 만들고 main을 쓰는 게 귀찮을 때가 있다. Jupyter에 자바 커널을 붙이면 한 칸(셀)씩 바로 실행할 수 있다.

3-1. 왜 쓰나

Anaconda는 원래 파이썬 데이터 분석 도구 묶음이고, 그 안의 Jupyter는 코드를 셀 단위로 실행하고 결과를 바로 아래에 보여 주는 노트다. 여기에 JJava라는 자바 커널을 설치하면 같은 노트에서 자바가 돈다. 클래스도 main도 없이 3 + 4만 써도 결과가 나온다. 이 교재의 짧은 예제를 하나씩 확인해 보기에 딱 좋다.

대신 파일 여러 개짜리 프로그램, 키보드 입력을 받는 프로그램, 데이터베이스 연결 프로그램은 VS Code가 훨씬 편하다. 실험은 Jupyter, 작품은 VS Code로 나눠 쓰면 된다.

3-2. Anaconda 설치

  1. anaconda.com/download에서 Anaconda Distribution 윈도우용을 받는다. 이메일을 묻는 화면이 나오면 입력하거나 건너뛰기 링크로 내려받는다.

  2. 설치 중 Just Me를 고르고, 나머지 선택지는 기본값 그대로 둔다. PATH에 추가하는 체크 칸은 기본값(체크 안 함) 그대로 두는 게 안전하다.

  3. 설치가 끝나면 시작 메뉴에 Anaconda Prompt와 Anaconda Navigator가 생긴다. Jupyter 관련 명령은 일반 cmd가 아니라 Anaconda Prompt에서 친다.

System.out.println(name + " " + age + " " + height + " " + isStudent + " " + grade + " " + score);

자바 변수는 이름표가 붙은 상자라고 생각하면 정확하다. int age는 "정수만 들어가는 age라는 상자를 만든다"는 뜻이다. 이 상자에 "스물일곱"을 넣으려고 하면 번역 단계에서 거절당한다. 파이썬처럼 아무거나 넣을 수 있는 이름표와 다르다.

5-2. 자주 쓰는 자료형

자료형담는 것예메모
int정수27, -3약 ±21억. 기본으로 쓰는 정수
long큰 정수3_000_000_000L끝에 L. 돈, 인구, 시간(밀리초)
double실수175.5기본으로 쓰는 실수
boolean참/거짓true, false조건문의 재료
char문자 하나'A', '가'작은따옴표
String문자열"김자바"큰따옴표. 대문자 S, 기본형이 아니라 클래스

이 밖에 byte, short, float도 있지만 일부러 고를 일은 거의 없다. 정수는 int, 실수는 double이 기본이고, 범위가 모자라면 long을 쓴다. 숫자 사이의 밑줄(3_000_000_000)은 읽기 쉬우라고 넣는 것으로, 값에는 영향이 없다.

Java
int max = Integer.MAX_VALUE;
System.out.println(max);
System.out.println(max + 1);     // 넘치면 맨 아래로 돌아간다

long big = 3_000_000_000L;       // int 범위 밖이면 long, 끝에 L
System.out.println(big);
System.out.println(0.1 + 0.2);   // 실수는 근삿값이다
실행 결과
2147483647
-2147483648
3000000000
0.30000000000000004

int의 최댓값에 1을 더했더니 갑자기 음수 최솟값이 됐다. 자동차 주행거리계가 999999 다음에 000000으로 돌아가는 것과 같다. 오류도 안 나고 조용히 틀리기 때문에 더 위험하다. 0.1 + 0.2가 0.3이 아닌 것도 버그가 아니다. 컴퓨터는 실수를 2진수 근삿값으로 저장한다. 그래서 돈 계산은 실수 대신 원 단위 정수로 하는 게 원칙이다.

import java.util.Scanner;

public class Bmi {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);

        System.out.print("키(cm): ");
        double heightCm = sc.nextDouble();
        System.out.print("몸무게(kg): ");
        double weight = sc.nextDouble();

        double h = heightCm / 100;

}

        }
        return b;
    }

        System.out.println();
        System.out.println(fibLoop(80));

import java.util.Arrays;
import java.util.Iterator;
import java.util.List;

public class RemoveTrap {
    public static void main(String[] args) {
        List<Integer> a = new ArrayList<>(Arrays.asList(2, 4, 4, 5, 6));
        for (int i = 0; i < a.size(); i++) {
            if (a.get(i) % 2 == 0) a.remove(i);    // 지우면 뒤 칸이 앞으로 당겨진다
        }
        System.out.println("앞에서부터 지우기: " + a);

        List<Integer> b = new ArrayList<>(Arrays.asList(2, 4, 4, 5, 6));
        for (int i = b.size() - 1; i >= 0; i--) {
            if (b.get(i) % 2 == 0) b.remove(i);
        }
        System.out.println("뒤에서부터 지우기: " + b);

        List<Integer> c = new ArrayList<>(Arrays.asList(2, 4, 4, 5, 6));
        Iterator<Integer> it = c.iterator();
        while (it.hasNext()) {
            if (it.next() % 2 == 0) it.remove();
        }
        System.out.println("Iterator로 지우기: " + c);

        List<Integer> d = new ArrayList<>(Arrays.asList(2, 4, 4, 5, 6));
        d.removeIf(n -> n % 2 == 0);
        System.out.println("removeIf: " + d);
    }
}

17-7. COMMIT과 ROLLBACK

INSERT, UPDATE, DELETE를 해도 바로 확정되지 않는다. 내 접속 창에서만 바뀐 걸로 보이고, 다른 사람(다른 접속, 자바 프로그램)에게는 안 보인다. COMMIT을 해야 확정되어 모두에게 보인다. 확정 전이라면 ROLLBACK으로 마지막 COMMIT 시점까지 되돌릴 수 있다. 이 "확정 전까지 한 묶음"을 트랜잭션이라고 한다.

SQL Developer에서 INSERT를 하고 COMMIT 없이 자바 프로그램으로 조회하면 데이터가 안 보인다. 18장을 하다가 "분명 넣었는데 왜 없지?" 싶으면 COMMIT부터 의심하자.

SelectAll.java
import java.sql.*;

public class SelectAll {
    static final String URL  = "jdbc:oracle:thin:@localhost:1521/FREEPDB1";

    public static void main(String[] args) {
        String sql = "SELECT id, name, major, score FROM student ORDER BY id";

        try (Connection conn = DriverManager.getConnection(URL, "study", "study1234");
             PreparedStatement ps = conn.prepareStatement(sql);
             ResultSet rs = ps.executeQuery()) {

            while (rs.next()) {                       // 다음 줄이 있으면 true, 그 줄로 이동
                int id = rs.getInt("id");
                String name = rs.getString("name");
                String major = rs.getString("major");
                int score = rs.getInt("score");
                System.out.printf("%d  %s  %s  %d%n", id, name, major, score);
            }
        } catch (SQLException e) {
            System.out.println("조회 실패: " + e.getMessage());
        }
    }
}

ResultSet은 결과 표 위에서 움직이는 손가락이다. 처음엔 첫 줄 바로 위에 있고, next()를 부를 때마다 한 줄 내려간다. 줄이 있으면 true, 더 없으면 false. 그래서 while (rs.next())가 "결과의 모든 줄에 대해"가 된다. 손가락이 가리키는 줄에서 getInt("열이름"), getString("열이름")으로 값을 꺼낸다. 데이터베이스의 NUMBER는 자바의 int(또는 long, double)로, VARCHAR2는 String으로 받는다.

import java.sql.*;

public class InsertOne {
    static final String URL  = "jdbc:oracle:thin:@localhost:1521/FREEPDB1";

    public static void main(String[] args) {
        String sql = "INSERT INTO student (name, major, score) VALUES (?, ?, ?)";

        try (Connection conn = DriverManager.getConnection(URL, "study", "study1234");
             PreparedStatement ps = conn.prepareStatement(sql)) {

            ps.setString(1, "한지우");      // 첫 번째 ? 자리
            ps.setString(2, "디자인");      // 두 번째 ? 자리
            ps.setInt(3, 83);              // 세 번째 ? 자리

            int rows = ps.executeUpdate(); // 바뀐 줄 수를 돌려준다
            System.out.println(rows + "명 등록");
        } catch (SQLException e) {
            System.out.println("등록 실패: " + e.getMessage());
        }
    }
}

값이 들어갈 자리를 ?로 비워 두고, setString(번호, 값)으로 채운다. 번호는 1부터 센다. 자바에서 유일하게 0이 아니라 1부터 세는 곳이라 처음에 꼭 한 번 틀린다. 데이터를 바꾸는 SQL은 executeQuery 대신 executeUpdate를 쓰고, 바뀐 줄 수가 돌아온다. 1이면 성공, 0이면 조건에 맞는 줄이 없었던 것이다.

17장에서 COMMIT을 강조했는데 여기에는 없다. JDBC 연결은 기본으로 자동 확정(auto-commit)이 켜져 있어서 executeUpdate가 끝날 때마다 COMMIT된다. 여러 SQL을 한 묶음으로 처리해야 할 때 이걸 끄는 법은 18-3 문제에서 다룬다.

public class StudentDao {

    List<Student> findAll() throws SQLException {

        List<Student> list = new ArrayList<>();

             PreparedStatement ps = conn.prepareStatement(sql);

                list.add(toStudent(rs));
            }
        }
        return list;
    }

    List<Student> findByMajor(String major) throws SQLException {
        String sql = "SELECT id, name, major, score FROM student WHERE major = ? ORDER BY score DESC";
        List<Student> list = new ArrayList<>();
        try (Connection conn = DBUtil.getConnection();
             PreparedStatement ps = conn.prepareStatement(sql)) {
            ps.setString(1, major);
            try (ResultSet rs = ps.executeQuery()) {
                while (rs.next()) list.add(toStudent(rs));
            }
        }
        return list;
    }

    int insert(String name, String major, int score) throws SQLException {
        String sql = "INSERT INTO student (name, major, score) VALUES (?, ?, ?)";
        try (Connection conn = DBUtil.getConnection();
             PreparedStatement ps = conn.prepareStatement(sql)) {
            ps.setString(1, name);
            ps.setString(2, major);
            ps.setInt(3, score);
            return ps.executeUpdate();
        }
    }

    int updateScore(int id, int score) throws SQLException {
        String sql = "UPDATE student SET score = ? WHERE id = ?";
        try (Connection conn = DBUtil.getConnection();
             PreparedStatement ps = conn.prepareStatement(sql)) {
            ps.setInt(1, score);
            ps.setInt(2, id);

        }
    }

import java.sql.*;

public class Transfer {
    static final String URL = "jdbc:oracle:thin:@localhost:1521/FREEPDB1";

    public static void main(String[] args) {
        String minus = "UPDATE account SET balance = balance - ? WHERE id = ? AND balance >= ?";
        String plus  = "UPDATE account SET balance = balance + ? WHERE id = ?";
        int amount = 30000;

        try (Connection conn = DriverManager.getConnection(URL, "study", "study1234")) {
            conn.setAutoCommit(false);                 // 자동 확정을 끈다
            try (PreparedStatement p1 = conn.prepareStatement(minus);
                 PreparedStatement p2 = conn.prepareStatement(plus)) {

                p1.setInt(1, amount); p1.setInt(2, 1); p1.setInt(3, amount);
                if (p1.executeUpdate() != 1) throw new SQLException("잔액 부족");

                p2.setInt(1, amount); p2.setInt(2, 2);
                if (p2.executeUpdate() != 1) throw new SQLException("받는 계좌 없음");

                conn.commit();                         // 둘 다 성공했을 때만 확정
                System.out.println("이체 완료");
            } catch (SQLException e) {
                conn.rollback();                       // 하나라도 실패하면 전부 취소
                System.out.println("이체 취소: " + e.getMessage());
            }
        } catch (SQLException e) {
            System.out.println("연결 실패: " + e.getMessage());
        }
    }
}

setAutoCommit(false)로 자동 확정을 끄면, 17-7의 SQL Developer처럼 COMMIT을 직접 해야 확정된다. 두 UPDATE가 모두 1줄씩 바뀌었을 때만 commit, 하나라도 문제가 있으면 rollback. 그래서 "빼기만 되고 넣기는 안 된" 상태가 절대 확정되지 않는다. 이게 17-7에서 말한 트랜잭션을 자바에서 쓰는 방법이다.

빼는 쪽 SQL의 AND balance >= ?는 잔액이 모자라면 조건에 걸리는 줄이 없어서 executeUpdate가 0을 돌려주게 만든다. 0이면 직접 예외를 던져서 catch의 rollback으로 보낸다(15-3). 한 번 더 실행하면 1번 계좌가 20,000원이라 "이체 취소: 잔액 부족"이 나온다. 테이블의 CHECK (balance >= 0)은 코드가 실수했을 때를 위한 마지막 안전망이다.

이 교재를 끝냈다면 자바 웹 개발자가 되는 길의 기초 구간을 지난 것이다. 그다음 순서는 대체로 이렇다.

  1. Git과 GitHub. 코드를 저장하고 기록을 남기는 도구. 지금 만든 성적 관리 프로그램부터 올려 두자. 나중에 포트폴리오가 된다.

  2. SQL 더 깊이. 테이블 두 개를 연결하는 JOIN, 서브쿼리, 인덱스. 실무 SQL의 절반이 JOIN이다.

  3. Maven 또는 Gradle. 2장에서 No build tools로 넘어간 그것. 라이브러리(jar)를 손으로 lib에 넣는 대신 이름과 버전만 적으면 알아서 받아 준다.

  4. HTML, CSS, JavaScript 기초. 웹 화면이 어떻게 생기는지 알아야 서버가 무엇을 돌려줘야 하는지 안다.

  5. Spring Boot. 자바 웹 서버를 만드는 사실상의 표준. 이 교재의 DAO, 인터페이스, 예외 처리 개념이 그대로 쓰인다. 18-8의 콘솔 메뉴가 웹 페이지로 바뀐다고 생각하면 된다.
